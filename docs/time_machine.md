# AI Site Time Machine — Technical Specification & Architecture

## 1. Executive Summary

The **AI Site Time Machine** is an enterprise-grade forensic and predictive engine embedded natively within the **FieldPulse AI** platform. It reconstructs the verifiable, authentic historical timeline of any construction schedule activity directly from database ground truth:

- **What happened?** (Timeline of field photos, voice notes, video records, QR scans, PM reviews, issues, and schedule modifications).
- **When did it happen?** (Timezone-safe UTC canonical timestamps).
- **What evidence proves it?** (Direct links to raw media, CV object detections, Whisper audio transcripts, and OCR/QR payloads).
- **Why is the activity delayed?** (Deterministic root cause correlation linking field breakdowns, material shortages, and weather events).
- **What will the delay affect downstream?** (Critical path and buffer slack traversal across the schedule dependency graph).

---

## 2. Core Architectural Principles

1. **Deterministic & Evidence-Grounded**: Zero synthetic timelines or hallucinatory LLM events. Every milestone, progress change, and delay driver cites immutable database records.
2. **Tamper-Evident SHA-256 Chaining**: Each event calculates an integrity hash chaining directly to its predecessor (`previous_hash`), forming a verifiable audit log.
3. **Strict Idempotency**: Pipeline retries or duplicate uploads are deduplicated via deterministic SHA-256 idempotency keys (`activity_id:event_type:source_id:timestamp`).
4. **Schedule Baselining**: Baseline start, end, duration, and planned progress curves are preserved in `schedule_baselines` snapshots.
5. **Zero-IDOR Security**: All endpoints enforce strict project-level role-based authorization (`require_project_access`).

#### Event Types (`EventType`)
- `PHOTO_CAPTURED`: Site inspection photo captured by field personnel
- `VOICE_UPDATE`: Field audio note transcribed via faster-whisper
- `VIDEO_CAPTURED`: Video recording documenting physical site conditions
- `QR_SCAN`: Material or equipment QR badge verification
- `PROGRESS_UPDATE`: Quantified progress delta applied to activity
- `PM_APPROVED`: Project Manager approval in review queue
- `PM_REJECTED`: Project Manager rejection with cited reason
- `EQUIPMENT_ISSUE`: Breakdown, hydraulic fault, or machinery shortage
- `MATERIAL_ISSUE`: Material stockout, delayed shipment, or quality defect
- `WEATHER_DELAY`: Rain, monsoon, mud, or extreme site weather
- `SAFETY_ISSUE`: Safety incident, near miss, or site stand-down
- `CORRECTIVE_ACTION_RESOLVED`: Verification that field blocker was resolved
- `ACTIVITY_CREATED`: Activity initialization into schedule baseline
- `SCHEDULE_UPDATED`: Modification to activity dates, duration, or dependencies
- `AI_DELAY_DETECTED`: Early-warning delay alert generated by forecasting service

## 4. Algorithmic Engines

### Delay Calculation Engine (`delay_engine.py`)
Computes:
1. **Planned vs Actual Progress**: Compares elapsed calendar duration against total duration to determine target linear progress.
2. **Schedule Variance**: `planned_percent - actual_percent`.
3. **Burn Rate & Forecast Completion**: Derives empirical daily completion rate from historical activity updates and projects estimated finish date.
4. **Delay Days**: `max(0, (forecast_finish.date() - planned_end.date()).days)`.
5. **Risk Classification**:
   - `LOW`: 0 delay days and negative/zero variance gap.
   - `MEDIUM`: 1–3 delay days on non-critical path.
   - `HIGH`: 4–7 delay days or any delay on critical path.
   - `CRITICAL`: >7 delay days or delay directly threatening milestone completion.

### Root Cause Engine (`root_cause_engine.py`)
Deterministic multi-pass correlation:
1. **Issue Analysis**: Scans open and unresolved field issues linked to the activity or matching activity keywords.
2. **Transcript Keyword Matching**: Analyzes faster-whisper transcripts from voice notes for equipment names, material types, and weather keywords.
3. **Stagnation Detection**: Identifies periods where days elapsed without progress increases or field evidence submissions.
4. **Confidence Scoring**: Assigns calibrated confidence (e.g. 0.85–0.95 for direct equipment issues, 0.75 for weather correlations, 0.65 for unrecorded stagnation).
5. **Supporting Evidence Attribution**: Cites specific event IDs and source IDs in `supporting_event_ids`.

### Downstream Impact Engine (`impact_engine.py`)
Graph traversal over schedule network:
1. **Adjacency Mapping**: Resolves predecessors and successors using `dependencies` (by ID and activity code).
2. **Buffer Slack Evaluation**:
   $$\text{Slack Days} = \max(0, (\text{Successor Planned Start} - \text{Predecessor Planned Finish}).\text{days})$$
3. **Delay Ripple Propagation**:
   $$\text{Successor Slip} = \max(0, \text{Predecessor Delay} - \text{Slack Days})$$
4. **Milestone Risk Flagging**: If any affected successor is marked as a milestone or has `critical_path = True`, marks the milestone at risk with projected slip days.

## 5. API Endpoints

All endpoints require Bearer JWT authentication and authorize user access against the project room.

- `GET /api/activities/{activity_id}`: Returns activity details with baseline attributes.
- `GET /api/activities/{activity_id}/timeline`: Returns paginated timeline events, activity KPI summary, root cause summary, and downstream impact. Filterable by `event_type`, `source_type`, `from`, and `to`.
- `GET /api/activities/{activity_id}/timeline/root-cause`: Returns isolated root cause breakdown with confidence and citations.
- `GET /api/activities/{activity_id}/timeline/impact`: Returns schedule dependency impact and milestones at risk.
- `POST /api/activities/{activity_id}/timeline/ask`: Deterministic natural language Q&A engine querying timeline events and returning grounded answers with citations.
- `GET /api/activities/{activity_id}/evidence/{evidence_id}`: Returns full forensic payload (photo URL, bounding boxes, Whisper transcripts, QR payloads, inspector metadata).
